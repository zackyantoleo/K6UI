    What these terms mean

    VUs simulate concurrent users. One VU repeatedly runs the complete request flow.

    Duration is how long the load remains fixed or ramps toward its target.

    Duration examples

    30s30 seconds
    5m5 minutes
    1h1 hour
    1h30m1 hour 30 minutes

    Staged mode: each stage defines a transition from the current VU count to the target VU count over the given time range.

    Iterations mode: every VU starts at once and runs the whole flow a fixed number of times, then the test ends. Total runs = VUs × iterations.

    Race burst: every VU runs the flow once and sends the race request at T0 + its offset, to test what happens when requests arrive at the same moment. The send times are k6's, not when the server received them.

    The test is considered failed (exit code ≠ 0) if these performance targets are not met — useful for CI/CD pipelines.

    Performance Targets

    p95 means 95% of requests must finish below this response time.
    Error rate is the percentage of HTTP requests allowed to fail.

    Outcome Targets

    How many responses of a request may get one label of its outcome rules (Request › Outcomes). The count is a number or a global variable such as {{QUOTA}}.

    No request has outcome rules yet. Add them under Request › Outcomes, then set targets on their labels here.

    What are Thresholds?

    Thresholds are the pass criteria for the test. If they are not met, k6 exits with exit code 99.

    Example: if you set p95 = 500ms and 5% of requests exceed it, the test is marked FAILED.

    Outcome targets check the labels of a request's outcome rules, for example success at most {{QUOTA}} in a race test: no more redeems than the quota allows. A target on a request that does not run (turned off, or in a turned-off group) is not checked, and the results say so.

            Variables
            
              
            
              
            
            

            
            
              
            How it works
            
              
            Reference a variable as {{name}} in a URL, header, or body — e.g. {{base_url}}/users.
            
              
            Names must start with a letter or underscore and contain only letters, digits, and underscores.
            
              
            If a request extracts a variable with the same name, the extracted value overrides the global one for the requests that follow.
            
            
            
          
            
        
            

        
        
            
          
            
            Headers automatically added to every request —
            e.g. Content-Type, Accept, or an Authorization token.
          
            
          
            
            
            
              
            Headers
            
              
            
              
            
            

            
            
              
            How it works
            
              
            These headers are sent with every request in the scenario, including Before and After sub-requests.
            
              
            Values can use {{name}} variables — e.g. Bearer {{token}} with a global or extracted variable.
            
              
            If a request defines a header with the same name, the request's value overrides the global one (names are case-insensitive).
            
            
            
          
            
        
            

        
        
            
          
            
            Give every iteration its own row from a CSV file — for example one login per user.
            Use a column name as {{column_name}} in any URL, header, or body.
          
            
          
            
            
            
              
            Data files
            
              
            
                The rows are saved inside the project file and written into the generated script.
                If a file holds passwords or tokens, treat both of them as secrets.

            How it works
            
              
            Each iteration reads one row. Next row for every iteration shares the file between all users, so no two iterations get the same row; One row per user gives user n the n-th row.
            
              
            Column names follow the variable rules: letters, digits, and underscores, not starting with a digit. Other columns are ignored.
            
              
            If a request extracts a variable with the same name as a column, {{name}} reads the file until that request has run, and the extracted value after it. Both override a global variable of that name.
            
              
            Files up to 5 MB each (10 MB in total). A file with no rows or no usable column is ignored, and its {{placeholders}} stay as text.
